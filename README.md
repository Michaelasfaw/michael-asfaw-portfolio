## What each project includes

- A concise explanation of the problem and intended audience.
- Technologies, data sources, and an architecture or workflow overview.
- Setup instructions, dependencies, and steps to reproduce the work.
- Results supported by metrics, screenshots, or example output.
- Limitations, lessons learned, and possible next steps.

Use [the project README template](docs/project-documentation/PROJECT_README_TEMPLATE.md) to document new work.

## Add a project

1. Choose the category that best describes the project's main purpose.
2. Create a descriptive folder, such as `database-projects/dvd-rental-revenue-analysis/`.
3. Add a project README, original code, and permitted supporting assets.
4. Use public or synthetic sample data and document its source and license.
5. Review staged files before committing; keep secrets and sensitive information outside Git.

For work spanning several categories, keep one primary project folder and link to it from related category READMEs.

## Responsible publishing

Publish only original work and material you have permission to share. Exclude employer-confidential code and data, proprietary files, credentials, personal identifiers, and restricted academic materials. Screenshots and notebook outputs need the same review as source files.

The ignore rules reduce accidental commits but do not replace a content review. Keep large datasets, generated models, and binary report files outside Git by default; document how to obtain approved inputs instead.
